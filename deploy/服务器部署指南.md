# 自媒体AI运营平台 · 服务器部署指南

> 本文针对 **Linux 云服务器公网部署**。Ubuntu 专版（含必做的 Nginx 加固）看 [Ubuntu部署指南.md](Ubuntu部署指南.md)，装好之后怎么用看 [操作手册](../docs/操作手册.md)。

---

## 一、需要安装什么依赖？

**只需要 Python 3.6 或更高版本。没有任何 pip 包要装。**

这不是省略，是实测结论：整个 `server.py` 只 import 标准库（`http.server` / `sqlite3` / `ssl` / `urllib` / `hashlib` / `hmac` / `secrets` / `gzip` / `zlib` / `threading`），所以项目里**没有也不需要 `requirements.txt`**。前端 `index.html` 是单文件 SPA，无构建步骤，不需要 Node。

| 项目 | 要求 | 说明 |
|---|---|---|
| Python | **3.6+** | 唯一硬依赖。主流云镜像（Ubuntu 20.04+/Debian 11+/CentOS 8+/Alibaba Cloud Linux）都自带 python3 |
| pip 包 | **零** | 不用 `pip install` 任何东西 |
| Node/npm | **不需要** | 前端无构建 |
| 数据库 | **不需要单独装** | SQLite 是 Python 标准库自带的 |
| Nginx | **可选** | 只在想上 HTTPS 或用 80 端口时才需要 |

唯一的外部网络要求：服务器要能**出网**（调用 MiniMax / 火山方舟 / Agnes 等 AI 接口，页面还会加载 Tailwind CDN）。

推荐配置：1 核 2G / 20G 硬盘足够。生成的图片视频会累积占盘，建议留 20G 以上。

## 二、一键部署（推荐）

### 方式 A：从你的 Windows 电脑一键推上去

双击 **`deploy\一键部署到服务器.bat`**，按提示输入服务器 IP 和 SSH 用户名，剩下全自动：

打包 → 上传 → 解包 → 安装 systemd 服务 → 放行端口 → 健康检查。

脚本会问你**一个关键问题**：要不要把本地 `data\` 一起传上去。

| 选择 | 结果 | 什么时候选 |
|---|---|---|
| **不传（默认）** | 服务器建全新空库，管理员密码随机生成 | 常规更新代码；服务器上已经有用户在用 |
| **传** | 服务器沿用你本地的账号密码、提示词、资产、图片视频 | **仅**首次部署，且线上还没有任何数据 |

⚠️ 选"传"会**覆盖**服务器上的 `data/`。如果线上已经有其他用户注册并生成了东西，他们的账号和资产会被抹掉。

项目根的 `.env` 会**随包上传**（密钥必须传，见第五节）。上传后 `deploy.sh` 把它转录进 `/etc/globalsales.env`（600、root 独占），再把项目目录里那份**覆写后删除** —— 不留在 `$RUN_USER` 可读、且理论上可能被 HTTP 摸到的地方。没有 `.env` 时脚本会提示你部署后手填。

它会刻意**排除**这些文件不上传：日志、`__pycache__`、`.claude`（记录过含密钥的命令原文）、临时 json。`demo.mp4`（55MB）**会**上传 —— 「操作演示」页直接播它，不传的话线上是个加载失败的黑框。上传耗时主要就花在这个文件上。

依赖 Windows 自带的 `ssh`/`scp`/`tar`（Win10 1803 以上都有）。

### 方式 B：在服务器上直接跑

代码已经在服务器上了（git clone 或手动传的），就在服务器执行：

```bash
cd /opt/globalsales && sudo bash deploy/deploy.sh
```

脚本是**幂等的** —— 重复执行安全，不会覆盖 `data/`，也不会重置已生成的管理员密码。

## 三、部署完必须知道的三件事

### 1. 云控制台放行端口

脚本能配置服务器本机的 ufw/firewalld，但**动不了云厂商的安全组**。去控制台手动放行：

| 云 | 位置 |
|---|---|
| 阿里云 | ECS → 安全组 → 配置规则 → 入方向 → 添加 8766/TCP |
| 腾讯云 | 云服务器 → 安全组 → 入站规则 |
| 华为云 | ECS → 安全组 → 入方向规则 |
| AWS | EC2 → Security Groups → Inbound rules |

### 2. 记下管理员密码

**账号名**：默认沿用你本地 `.env` 里的 `GS_ADMIN_USER`（通常就是你自己的用户名）；本地没有才回落到 `admin`。

**密码**：首次部署时脚本会**随机生成**一个 20 位密码并打印出来（只打印这一次）。忘了可以查：

```bash
sudo grep GS_ADMIN_PASS /etc/globalsales.env
```

> ⚠️ 源码里的默认账号 `martinxie / sunny520` 是公开的，任何看过这份代码的人都知道。部署脚本用环境变量把密码盖成随机值了，所以**公网上跑的不是这个密码**。如果你手动启动而没走脚本，务必自己改。

> 这组账号密码**只在首次建库时生效**（`data/app.db` 不存在时）。如果你在上一步选了"把本地 data 传上去"，库里已经有账号了 —— 请用你本地原来的用户名密码登录，脚本打印的那组不会生效。

### 3. 用户数据不会自动跟过去

部署**默认不传** `data/`，所以服务器上是全新空库：

| 你本地的东西 | 会过去吗 |
|---|---|
| 管理员账号密码 | ❌ 新建，密码随机 |
| 资产（图片/视频/文章） | ❌ |
| 提示词（你改过的那些） | ❌ |
| 大模型配置 | ❌ |
| API 密钥 | ✅ 随 `.env` 过去 |

想带过去就在 `.bat` 的提示里选"传"。这时脚本还会自动做一件事：`assets.file_path` 存的是**绝对路径**（本地是 `E:\ClaudeOut\...`），迁到 Linux 后会全部读不出来；`deploy.sh` 会按文件名把它们重指到服务器的 `data/users/<uid>/`，并打印迁移条数。找不到实体文件的行保持原样不动（宁可留着能查，也不改成一个错路径）。

**新用户注册时拿到什么？** 提示词会 seed 一份 —— 但给的是**源码内置的 `defaultPrompts` 模板**，不是读你数据库里那些。你后来改过的提示词，新用户拿不到。模型配置刻意不 seed，新用户列表为空需自行添加。资产、工作区快照一概没有。

## 四、日常运维

```bash
systemctl restart globalsales     # 重启
systemctl status globalsales      # 看状态
tail -f /var/log/globalsales.log  # 看实时日志
journalctl -u globalsales -n 50   # 看崩溃原因
```

改配置（API 密钥、端口、管理员密码）：

```bash
sudo nano /etc/globalsales.env && sudo systemctl restart globalsales
```

### 更新代码

再跑一次一键部署即可。`data/` 不会被动，用户资产和账号全部保留。

### 备份（重要）

要备份的只有 `data/` 一个目录 —— SQLite 用户库 + 用户生成的图片视频：

```bash
tar -czf /root/gs-backup-$(date +%F).tar.gz -C /opt/globalsales data
```

## 五、配置项一览

配置有两个来源，**优先级：真实环境变量 > 项目根 `.env`**。服务器上用 systemd 的 `/etc/globalsales.env`，本机开发用项目根的 `.env`（`server.py` 启动时由 `_load_dotenv()` 读入 `os.environ`，加载成功会打印 `[env] 已从 .env 加载 N 个变量`）。两处都不用改源码。

首次部署照 `.env.example` 复制一份：

```bash
cp .env.example .env && chmod 600 .env && nano .env
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `GS_PORT` | `8766` | 监听端口 |
| `GS_ADMIN_USER` | `martinxie` | 首次建库时的管理员用户名 |
| `GS_ADMIN_PASS` | `sunny520` | 首次建库时的管理员密码，**部署脚本会换成随机值** |
| `GS_COOKIE_SECURE` | `0` | 套了 HTTPS 后改 `1`；纯 http 时**必须留 0**，否则浏览器丢 cookie 会永远登不上 |
| `MM_API_KEY` | **空** | MiniMax |
| `HY_API_KEY` | **空** | 腾讯混元 |
| `AGNES_API_KEY` | **空** | Agnes AI |
| `ARK_PLAN_API_KEY` | **空** | 火山方舟 Agent Plan —— **文案主力**，7 个文本模块默认都走它 |
| `ARK_API_KEY` | **空** | 火山方舟 Seedream —— **出图主力**，图片类唯一可用模型 |
| `SEEDANCE_MINI_API_KEY` | **空** | Seedance 2 Mini 视频 |

> `ARK_PLAN_API_KEY` 和 `ARK_API_KEY` 是两把不同的 key（一把打
> `api/plan/v3/chat/completions`，一把打 `api/v3/images/generations`），
> 互换会报 401 / 404。只配后者的话站点能登录能出图，但文案全线鉴权失败。

**6 个密钥的默认值是空字符串，源码里一个字面量都没有。** 没配就是没配 —— 对应模型会返回鉴权错误。这是故意的：宁可明确报错，也不要为了"开箱能跑"把密钥焊回源码，因为源码会被拷贝、打包、上传，字面量跟着一起走。

管理员在「大模型配置」页保存内置模型密钥时，走 `_persist_env_keys()` 写进 `.env`（同名行原地替换、不追加重复行、值含换行直接拒绝），并同步更新 `os.environ` + 模块常量 + `API_ROUTES` 的 `auth_key`，**无需重启即时生效**。

## 六、安全说明：公网部署前做了什么加固

绑公网 IP 和在自己电脑上跑，威胁模型完全不同。写这份指南前实测了运行中的服务，发现并修掉了 5 个洞，每一个在公网上都是完整失陷：

| 问题 | 加固前实测 | 现在 |
|---|---|---|
| 源码可下载 | `GET /server.py` → 200，143KB，**5 个 API 密钥明文** | 404 |
| 用户库可下载 | `GET /data/app.db` → 200，348KB，**用户名 + 密码哈希 + 会话 token** | 404 |
| 匿名改写源码 | `POST /api/sync_config` 无 cookie 可达，而它会 `open(server.py,'w')` → **等于远程代码执行** | 401，且需管理员 |
| 商品抓取 SSRF | `?url=http://127.0.0.1:8766/...` → 200，服务器替攻击者读内网。云上换 `169.254.169.254` 就能拿实例临时凭证 | 400 |
| 万能代理 SSRF | `/api/custom_model` 只校验 `^https?://`，匿名可用 | 401 + 内网地址拦截 |

前两个的根因是同一个：`ProxyHandler` 继承 `SimpleHTTPRequestHandler`，它默认**把整个工作目录当网站根目录**。修法是在 `do_GET` 最前面加**静态文件白名单**（不是黑名单 —— 黑名单每多一个文件就多一个漏口），只放行 `index.html` 和几个图标，其余一律 404。

其他既有机制：

- 密码 PBKDF2-SHA256 20 万轮加盐，不可逆
- 所有 SQL 用 `?` 参数化占位符，无字符串拼接 → 无注入面
- 用户数据 `WHERE user_id = ?` 隔离，A 用户拿不到 B 用户的资产
- 会话 cookie `HttpOnly` + `SameSite=Strict`（JS 读不到，跨站不带）
- 用户媒体只能通过 `/api/data/media/<id>` 鉴权后读取，路径由服务端从数据库拼，客户端传不进文件路径
- systemd 用 `ProtectSystem=full` + `ReadWritePaths=data` 跑在无登录 shell 的专用账号下 —— 就算应用层出洞也改不动 `server.py`
- `data/` 目录权限 700，`/etc/globalsales.env` 权限 600

### 还需要你留意的

1. **源码里已经没有任何密钥字面量。** `index.html` 的 5 个 key（约 2820-2850 行，变量和引用保留，值为 `''`）和 `server.py` 的 5 个常量（现在是 `os.environ.get(VAR, '')`，无回落字面量）都清空了。首页必须允许下载，写在那里的密钥会随页面发给每个访客，F12 或 `curl` 首页就能抄走；`server.py` 虽然 HTTP 拿不到（404），但会跟着任何一次拷贝/打包/上传走。清空后功能不受影响：`USE_PROXY` 为真时请求发给后端 `/api/*`，`build_headers()` 用服务端密钥重新构造请求头，浏览器带来的那个本来就被丢掉。

   真正的密钥只存在两个地方：服务器上的 `/etc/globalsales.env`（600），或项目根的 `.env`（已在 `.gitignore`，且被静态黑名单挡死）。部署后自查：
   ```bash
   grep -rIl -E "(sk-|ark-)[A-Za-z0-9_-]{30,}" \
     --exclude-dir=data --exclude-dir=.git --exclude-dir=.claude --exclude-dir=__pycache__ .
   ```
   只应列出 `.env` 本身。长度门槛写 30 并排除 `.claude`，是因为宽松版（20 且不排除）会误报
   —— 技能包目录名 `ark-agentplan-seedream-skill` 就会被命中，看着像漏了密钥其实没有。
   另外注意两个容易被忘的残留源：
   - `__pycache__/*.pyc` —— 编译产物会把旧字面量的字节留下来，清源码后要顺手删掉整个目录
   - `.claude/settings.local.json` —— 记录允许过的 Bash 命令原文，调试时 `curl -H "Authorization: Bearer ..."` 会被抄进来（实测抄到过 6 条）。已加进 `.gitignore` 和静态黑名单

2. **默认是 http 明文**。登录密码在网络上不加密。有域名的话强烈建议套一层 Caddy（自动签 HTTPS），然后设 `GS_COOKIE_SECURE=1`：
   ```
   your-domain.com {
       reverse_proxy localhost:8766
   }
   ```
3. **`ssl._create_unverified_context()`** 对外调用不验证证书。这是为了绕过部分云环境的自签名证书拦截，属于有意取舍；如果你的服务器出网正常，可以改回默认验证。
4. **注册接口默认开放**。不想让陌生人注册的话，需要加邀请码或在 Nginx 层限制 `/api/auth/register`。

## 七、故障排查

| 现象 | 排查 |
|---|---|
| 浏览器打不开 | ① `curl localhost:8766/index.html` 在服务器上通不通 ② 云安全组放行了吗 ③ `systemctl status globalsales` |
| 服务起不来 | `journalctl -u globalsales -n 50 --no-pager`，最常见是端口被占 |
| 登录一直失败 | 看是不是 `GS_COOKIE_SECURE=1` 但用的 http 访问 → 浏览器会静默丢 cookie。改回 0 |
| 图片/视频生成失败 | 日志里会打印厂商返回的错误。多半是 key 余额用尽（MiniMax 会返回 `status_code: 2056`；Agnes 返回 403 `insufficient_user_quota` 并附剩余额度） |
| 视频报 400 `duration is not an allowed request field` | 厂商 2026-08 换了 `/v1/videos` 请求体：`duration`/`resolution` 废弃，改用 `mode:'ti2vid'` + `seconds`（**字符串**）+ `size:'720P'`。代码已修，schema 见 [技术架构文档](../docs/技术架构文档.md) |
| 视频报 400 `Input should be 'ti2vid', ...` | `mode` 是枚举，文生视频只能填 `'ti2vid'`。代码已修 |
| 页面样式全乱 | Tailwind CDN 加载不出来，服务器或客户端出网被墙 |
| 端口想改 | 改 `/etc/globalsales.env` 的 `GS_PORT`，重启，并同步放行新端口 |
