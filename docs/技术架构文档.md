### 三条设计约束（解释了大部分技术选择）

**1. 零依赖。** 后端只 import 标准库，前端无构建步骤。代价是没有 ORM、没有模板引擎、没有前端框架；收益是 `git clone` 完直接 `python3 server.py` 就能跑，部署不需要 venv / npm / Docker，运维面小到只有一个 Python 进程加一个 SQLite 文件。

**2. 密钥只在服务端。** 前端 5 个 key 常量值为空串，请求发给同源 `/api/*`，由 `build_headers()` 用服务端密钥重构请求头。这是 `API_ROUTES` 代理层存在的唯一理由 —— 否则前端可以直连厂商。

**3. 单文件优先。** 前端不拆是刻意的：一个 HTML 文件可以邮件发、U 盘拷、双击开，对非技术使用者的分发成本最低。代价是一万五千行的单文件编辑体验，靠 `section-*` / 函数名前缀（`vc*` / `ts*` / `src*`）做逻辑分区。

## 二、前端

### 2.1 页面结构

24 个 `<section id="section-*">` **同时存在于 DOM**，但**一次只显示一个**：`.section { display: none }` + `.section.active { display: block }`，`scrollToSection()` 摘掉旧页的 `.active`、给新页加上，再把 `mainContent.scrollTop` 归零。不销毁不重建。这带来三个后果：

- **好处**：跨页面状态天然保留（切走再切回，输入框内容还在），无需状态管理库
- **好处**：首屏只 layout 一个 section，不再一次性排版近 900KB 的 DOM
- **代价**：没有 URL 路由，刷新回到默认页（`currentSection` 初值 `hotspot`，由 `init()` 点亮）

导航分 7 组（`nav-divider` 分隔）：

| 组 | nav id | 说明 |
|---|---|---|
| 1 | `sourcing` | 选品（置顶，入口） |
| 2 | `hotspot` `product` `article` `video` `freeqa` | 内容主链路，有数据传递 |
| 3 | `text-studio` `image` `video-create` `comment` `smart-reply` | 独立工具 |
| 4 | `accounts`🔒 `assets` `ip-stats`🔒 | 资产与运维 |
| 5 | `commerce-platforms` `social-platforms` `holidays` `metrics` | 静态知识库 |
| 6 | `prompts` `models` `model-shop` | 配置 |
| 7 | `demo` `user-center` `users`🔒 | 账号与上手 |

**高亮同步**：由 `scrollToSection()` 直接调 `updateNavActive()`，当前页就是刚点的那一项，不存在错位可能。

> 改版历史：早期是"24 个 section 纵向堆叠、`scrollIntoView` 滚过去"的长页面，高亮靠 `mainContent` 的 scroll 监听（100ms 防抖）按 `scrollTop + 150` 反推当前 section，比对一份**手写的 sections 顺序数组**。那份数组必须跟 DOM 顺序手工同步，曾漏掉 5 项导致高亮停在上一个菜单上。改成单页后 scroll 监听和数组一并删除，这类隐患从根上消失。

**两个与单页导航耦合的约束**（改动这块必须一起看）：

1. **受限 section 用 `.section-locked` 类锁，不能用内联 `display`。** 非管理员看不到 `ip-stats` / `accounts` / `users`，`applyRoleVisibility()` 给它们加 `.section-locked`（带 `!important`，压过 `.active`）。早期用的是 `el.style.display='none'`，内联优先级高于类，会导致这几页即使 `.active` 也不显示 —— 右侧一片空白。
2. **当前页被锁掉时必须踢回安全页。** 管理员停在「账号管理」上退出、换普通用户登进来，`currentSection` 还是 `accounts`，那页被锁着、又没有别的页是 `.active`，工作区彻底空白且只能刷新。`applyRoleVisibility()` 末尾检查 `RESTRICTED_SECTIONS[currentSection]`，命中就 `scrollToSection('hotspot')`。`scrollToSection()` 自身也挡两道：目标不存在、或目标带 `.section-locked`，都原地不动。

### 2.2 模型层

前端不硬编码"哪个模块用哪个模型"，而是三级降级：

```
getModuleModelId(moduleKey)
  ① window._moduleDefaultsCache   ← 后端 user_module_defaults 表（用户显式「设为默认」）
     ↓ 校验：该 model 存在 且 type 匹配 MODULE_MODEL_TYPE[moduleKey]
  ② DEFAULT_MODULE_MODELS[moduleKey]   ← 源码内置默认
  ③ getModelsByType(type)[0]           ← 该类型第一个可用模型
```

`getModelsByType()` **过滤掉 `status === 'disabled'`** —— 这是"禁用模型不出现在任何下拉里"的实现点。12 个内置模型中 7 个当前禁用，用户选不到必然失败的选项。

`DEFAULT_MODULE_MODELS` 里 7 个文本模块（含 `freeqa`）默认都指向 **`ark-plan-text`**（火山方舟 Agent Plan），不是 `ark-text`。代码注释记录了原因：`coding/v3` 实测 400 `InvalidSubscription`、MiniMax 实测 429 Token Plan 上限，两条老链路同时挂掉，Agent Plan 端点是当时唯一可用的。**这也是 `ARK_PLAN_API_KEY` 必配的原因** —— 它和 `ARK_API_KEY` 是两把不同的 key，见 5.1。

**模型选择刻意不进工作区快照。** 早期版本存过，结果「设为默认」被 30 秒后的工作区回写打回。现在两条持久化路径完全分开：模型走 `POST /api/data/module_defaults`，其余状态走 `POST /api/data/appdata`。

**视频模型的双层映射**（历史债，但有意保留）：

```
model_id ('agnes-video-25')
  → _videoShortKey() → 短键 ('agnes25')
  → 四个 dispatch 点的 if/else 分支 → callAgnesVideo25()
```

短键存在是因为早期代码用 `'agnes'`/`'hunyuan'` 这类字符串做分派，散落在 4 处（`generateVideo` 单段/分镜、`vcGenerate`、`vcGenSegments`）。新增视频模型需要同时改：`defaultModels`、`VIDEO_MODEL_BUILTIN`、`_videoShortKey` 映射、4 处 dispatch、5 处显示名映射。这是**加新视频模型时最容易漏的地方**。

### 2.3 工作区持久化

```
用户打字
  → _onWorkspaceInput（事件委托挂 document，覆盖动态 innerHTML 生成的框）
  → persistWorkspaceSoon()  防抖 2 秒
  → saveAppData()
       ├── captureWorkspace()  收集 7 类状态
       ├── 体积核算：> 512KB 时丢文章正文（保留标题 + truncated 标记）
       └── POST /api/data/appdata
```

三条触发路径：**打字停 2 秒** / **30 秒定时器** / **beforeunload**。

`captureWorkspace()` 保存的 7 类：`inputs`（8 个白名单输入框）、`scriptContent`、`storyboard`、`productContext`（含手工改过的核对区 HTML + 纯文本）、`currentArticle`（标题+正文+3 图）、`selections`（平台/搜索源）、`savedAt`。

**两个易错点，注释里都标了**：
- 脚本和分镜读的是 `#scriptContent` / `#vcStoryboardView`（**真值**），不是 `#scriptEditor` / `#vcStoryboardEdit`（编辑态临时框）
- 防抖 2 秒是刻意值：更短反复打后端，更长会丢最后一个字

### 2.4 XSS 边界

抓取回来的第三方内容（商品标题、评论、搜索结果）一律视为不可信：

- 文本走 `escapeHtml()`
- 属性走 `escapeAttr()`
- 链接走 `safeUrl()` + `rel="noopener noreferrer"`
- 可编辑单元格**读 `textContent` 存、`escapeHtml` 渲染**，不开 `innerHTML` 直写通道

### 2.5 视觉令牌层

全站配色/圆角/阴影/字体集中在 `index.html` 开头 `<style>` 里的 `:root`，只有一个 `<style>` 块（Tailwind CDN 只用工具类，不参与主题）。改主题**只改这一处**，不用全文替换十六进制值。

**底色四层的关键是页底比卡片更暗：**

```
--bg-primary   #020617   页底（最暗）
--bg-secondary #0f172a   卡片
--bg-tertiary  #1e293b   抬起层
--bg-hover     #334155   悬停
--border       #1e293b   常规边框（比卡片底同色或更暗）
--border-strong #334155  强调边框
```

改版前是反的：页底和卡片只差一档、边框却更亮（`#334155`），层次全靠亮边框撑，整屏读起来灰扁。现在层次靠底色差拉开、边框压暗。

**文字五级**：`--text-primary` / `--text-strong` / `--text-body` / `--text-secondary` / `--text-dim`。注意 `--text-secondary` 被引用 292 处，是全站次要文字的既有承载者，**保持 slate-400 不要整体调亮** —— 调亮会把"主/次"两级压平。需要亮一档时显式用 `--text-body`。

**主色是渐变而不是单色**：靛蓝→紫（`--grad-primary`）做主动作，玫红→粉（`--grad-accent`）做一屏只该有一个的强调动作，另有 `--grad-success` / `--grad-info`。三个注意点：

1. **渐变不能做 CSS transition。** hover 态另给一条同角度、更深的渐变（`--grad-primary-hover`），靠切换实现"按下去更深"的观感。
2. **写死在 HTML 里的渐变必须和 JS 里的字符串逐字一致。** `switchAuthTab()` 手写了一份选中态渐变，早期它写的是实色 `var(--accent)`，切一次 tab 就掉回实色，看着像 bug。
3. **`background-clip:text` 要先给实色 `color` 兜底**，再 `-webkit-text-fill-color:transparent` —— 不支持的引擎会忽略后者，落到实色上而不是变成透明字。

**毛玻璃与阴影**：`--glass`（`rgba(15,23,42,.8)`）+ `backdrop-filter: blur(var(--blur-md))` 用在卡片和侧边栏；阴影五档 `--shadow-sm/md/lg/xl/2xl`。`backdrop-filter` 不支持时安静退化成半透明底，观感略平但不破版。页面底纹是 `body::before` 上两团很淡的径向渐变（`position:fixed`，`pointer-events:none`），**零位图** —— 参考站同样如此，整站 `url()` 零匹配。

**字体是无衬线，不是宋体。** 一条 `--font-stack` 同时服务中英文，靠**逐字回退**工作，所以顺序有讲究：拉丁字体在前（`-apple-system` / `Segoe UI` / `Roboto`），CJK 在后（`PingFang SC` / `Microsoft YaHei` / `Noto Sans CJK SC`）。CJK 字体自带完整拉丁字形，放前面会把英文一起吞掉。改版前用的是 Calibri + 宋体（serif），宋体在深色底上笔画细、发虚。

**两处刻意不参与主题化**：

- 富文本导出的 7 个标记色（`RICH_INLINE_STYLES` / `RICH_BLOCK_STYLES`）—— 它们要在公众号/小红书后台的白底上显示，不能跟站内深色底绑定。底色压深后重算过一遍对比度，7 个色全部提升（如 4.85→5.48）。
- HTML `style="` 属性里 115 处硬编码十六进制值（57 个不同色值）—— 已知债务，改主题时这些不跟着变。

**对比度下限**：小字号白字底不低于 3.0。`.btn-warning` 原来用 `#f59e0b` 配白字只有 2.15，`.asset-tab.active` 用 `--accent-light` 只有 2.98，都在改版时压深了一档。

**彩色菜单图标**：24 个 `#nav-* .nav-icon { color: ... }` 规则，一项一色，作用是让用户靠颜色而不是读字定位菜单。三条约束：

- 全部取 tailwind **400/500 档** —— 300 档在深色底上发白糊成一片，600 档压得太暗；
- **同分组内相邻两项色相至少隔 30°**。跨分组不要求，中间有 `nav-divider` 隔着；
- 24 个色值互不重复。早期 `product` 和 `commerce-platforms` 撞了同一个蓝（都是电商语义），但两者分属不同组、图标形状还一样，撞色后光看左边那列分不出来。

图标 SVG 用 `stroke="currentColor"`，所以只改 `color` 就够，不必碰 24 处 HTML，也避免再往 `style=""` 里加硬编码色值。常态 `opacity: .85`、hover/选中给足 1 —— 深色底上铺满饱和色会吵。最暗一档（`video-create` 靛蓝）压到 .85 后对比度仍有 **4.78**，24 个全部在 4.7 以上。

### 2.6 ESC 关闭弹窗

一个挂在 `document` 上的全局 `keydown`（`initEscToClose()`，由 `init()` 调用），而不是给每个弹窗各挂一个。原因：弹窗内的输入框 / `contenteditable` 会吃掉按键，挂在弹窗自己身上更容易漏；动态创建的弹窗也没有固定挂载点。

```
ESC → closeTopmostModal()
       ① escDynamicStack 栈顶（动态弹窗，z-index 9999）
       ② ESC_MODALS 倒序（5 个静态弹窗）
       都没有 → 返回 false，不拦事件
```

关闭一律走各自**已有的 `close*()` 函数**，不是简单 `display:none` —— 那几个函数还要清定时器（`closeBindModal` 的 `bindCountdownTimer`）、重置编辑态（`editingPromptId` / `editingModelId`）、恢复 `body.overflow`。绕过它们会留下脏状态。

动态弹窗（图片大图预览、资产详情）创建时 `pushEscLayer(el, closeFn)`、关闭后 `popEscLayer(el)`；点遮罩和按 ESC 共用同一个 close 函数，且必须可重复调用 —— 点一下遮罩再按 ESC 是很自然的操作。

**判可见不能图省事**，两个坑都踩过：

1. **不能用 `offsetParent !== null`。** 按规范 `position:fixed` 元素的 `offsetParent` 恒为 `null`，与显示无关。5 个静态弹窗全是 fixed，用它判等于一个都关不掉 —— 第一版就是这么写的，实测才发现。
2. **不能只看元素自己的 computed display。** computed display 不会因父级 `display:none` 变成 `none`。`promptEditModal` / `modelEditModal` 挂在 `section-prompts` / `section-models` **内部**，单页导航下切到别页时父 section 是 `display:none`，弹窗自己仍算 `flex` —— 只看自己会把用户看不见的弹窗当成最上层，ESC 打在空气上。

所以用 `isModalVisible()` 往上走到 `body`，任何一层 `none` 就算不可见。

两条刻意的例外：**`authGate`（登录墙）不在 `ESC_MODALS` 里** —— 它不是可关闭弹窗，ESC 能关掉就等于绕过登录；**`e.isComposing` 时直接返回** —— 中文输入法候选窗开着时按 ESC 是"取消候选"，不该顺带关弹窗，这是本站主场景。只有真的关掉了才 `preventDefault()`，否则不妨碍其它 ESC 用法。

## 三、后端

### 3.1 请求处理链

```
请求进入
  ↓
do_GET / do_HEAD：先跑 _static_block_reason()  ← 唯一的静态文件闸门
  ↓ 不通过 → 404（.py / .db / .env / data/ / .git/ 全挡在这里）
  ↓
路径分派：
  ├── /                      → 302 /index.html?nocache=<ts>
  ├── /index.html            → 直接读文件，禁 304、禁缓存
  ├── /demo.mp4              → _serve_demo_video()  Range 分片
  ├── /api/auth|data|admin|ip_stats  → handle_user_api()  ← 15 个 _api_* 处理器
  ├── /api/web_search|product_scrape  → 抓取端点 ⚠️ 无鉴权
  ├── /api/sync_config       → _require_admin
  ├── /api/custom_model      → _require_auth + _assert_public_url
  └── API_ROUTES 查表        → 厂商代理转发 ⚠️ 无鉴权
```

`do_POST` **不跑**静态闸门（POST 落不到静态文件服务，不构成泄露）。`do_DELETE` 只放行 `/api/data/*` 和 `/api/admin/*`。

### 3.2 厂商代理层

`API_ROUTES` 是一张 17 条的查表（16 条 `bearer` + 1 条 `x-api-key`，后者是 MiniMax 的 Anthropic 兼容端点），每条描述"如何把一个同源请求改写成一个厂商请求"：

```python
'/api/agnes_video25_submit': {
    'url': 'https://apihub.agnes-ai.com/v1/videos',
    'method': 'POST',
    'auth_type': 'bearer',           # 或 'x-api-key'（仅 /api/text）
    'auth_key': AGNES_API_KEY,       # 服务端常量，前端拿不到
    'extra_headers': {},
    'inject_body': {'model': 'agnes-video-2.5'},   # 仅当 body 里没有该键才注入
    'remove_params': [...]           # 删厂商不支持的字段
}
```

**GET 路由支持前缀匹配** —— 这是异步任务轮询能穿过代理的原因：

```
GET /api/agnes_video25_query/video_xxx
  → route['url'] + '/video_xxx'
  → GET https://apihub.agnes-ai.com/v1/videos/video_xxx
```

**同厂商的不同模型走独立路由，不复用。** Agnes V2.0 和 2.5 打的是同一个 `/v1/videos` 端点、只有 `model` 值不同，但仍配了两条路由 —— 因为 `sync_models_to_files` 会按 `route_by_id` **就地改写路由 URL**，共用一条的话在「大模型配置」里改 2.5 的 Base URL 会把 V2.0 一起改掉。

**超时**：POST 300s（视频提交可能很慢），GET 180s。

#### Agnes `/v1/videos` 请求体 schema（2026-08-24 实测）

厂商把 V2.0 和 2.5 统一成了同一套请求体，**旧字段会被硬拒**。这次变更直接造成了用户报的「视频生成失败 HTTP 400 `duration is not an allowed request field`」—— 当时 `callAgnesVideo()` 还在发 `duration` + `size:'768x768'`。

| 字段 | 状态 | 实测结果 |
|---|---|---|
| `duration` | ❌ 已废弃 | 400 `duration is not an allowed request field` |
| `resolution` | ❌ 已废弃 | 400 `resolution is not an allowed request field` |
| `size` | ⚠️ 语义变了 | 只收档位串 `'720P'`；`'768x768'` 这类像素写法不再接受 |
| `mode` | ✅ **新增必填，且是枚举** | 只收 `'ti2vid'` / `'keyframes'` / `'multi_reference'`。文生视频用 **`'ti2vid'`**；填别的报 400 `Input should be 'ti2vid', 'keyframes' or 'multi_reference'` |
| `seconds` | ✅ 取代 `duration` | **必须是字符串**。传数字报 `json: cannot unmarshal number into Go struct field taskSubmitReqAlias.seconds of type string` |
| `aspect_ratio` | ✅ | 白名单 `21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16` |

实测通过的组合（V2.0 直连厂商 HTTP 200 `queued`；2.5 同 schema）：

```json
{"model": "...", "prompt": "...", "mode": "ti2vid",
 "seconds": "5", "size": "720P", "aspect_ratio": "16:9", "n": 1}
```

> `mode` 这一格踩过两次坑：先漏了整个字段（400 `duration ...` 修完才暴露出来），补上时又按字面意思填了 `'text'`，用户拿到第二条 400 才知道它是枚举。**不要凭字段名猜取值** —— 厂商的错误信息会把合法枚举列全，照抄即可。回包里的 `size` 是厂商换算后的实际像素（如 `1088x832`），不等于你传的档位，属正常。

**两个容易被误判成参数错的响应**，前端已分别给出针对性提示而不是笼统报「提交失败」：

- `503 {"code":"video_queue_full"}` / `503 Service busy: inference slot is in use` —— 厂商队列或推理槽占满，等一两分钟重试即可
- `429 video generation rate limit exceeded` —— 视频接口限流 **6 次/分钟**

限流这条要紧：前端轮询是 5 秒一轮（12 次/分钟），排队稍久必然撞上，所以 `callAgnesVideo` 对 429 做**退避重试**而不是当失败 —— 否则任务明明在正常排队却被报成「生成失败」。

完成后的视频地址在**顶层 `url`**，`metadata` 整个是 `null`。完成响应的顶层键还有 `video_id` / `status` / `progress` / `seconds` / `size` / `expires_at` 等。

> 这一格记错过一次：早前写的是「地址在 `metadata.url`，不在 `url`」，正好说反了。2026-08-24 走本站 `/api/agnes_video_submit` → `/api/agnes_video_query/<task_id>` 端到端复测才纠正（拿到 1,306,842 字节 `video/mp4`，魔数 `ftypisom`）。前端仍保留 `findFirstVideoUrl()` 递归兜底 —— 厂商换过一次字段位置，写死路径就会再坏一次。

**轮询用路径段，不是 query string**：前端拼的是 `AGNES_VIDEO_QUERY_URL + '/' + encodeURIComponent(taskId)`，后端 `/api/agnes_video_query` 走前缀匹配转发（`server.py` 2425 行附近）。写成 `?id=xxx` 会把 id 丢掉，厂商返回 404 `Invalid URL (GET /v1/videos)`。

### 3.3 数据模型

9 张表，SQLite + WAL + `foreign_keys=ON`：

```
users (id, username UNIQUE, pass_hash, salt, role, created_at, prompts_seeded)
  │  + UNIQUE INDEX users(username COLLATE NOCASE)  ← 用户名不区分大小写
  │  以下 7 张表的 user_id 均为 REFERENCES users(id) ON DELETE CASCADE
  ├── sessions (token PK, user_id, created_at, expires_at)  + INDEX (user_id)
  ├── assets (id, user_id, kind, title, content, url, file_path, platform, model, created_at)
  │     + INDEX (user_id, kind)
  ├── user_prompts    UNIQUE(user_id, prompt_id)
  ├── user_models     UNIQUE(user_id, model_id)
  ├── user_module_defaults  PK(user_id, module_key)
  ├── user_accounts   (id, user_id, data, created_at)
  └── user_appdata    PK(user_id)        ← 工作区快照，单行覆盖

ip_stats (id, data, updated_at)          ← 全局单行，admin only
```

只有 3 个索引：`idx_users_username_nocase`（UNIQUE）、`idx_assets_user(user_id, kind)`、`idx_sessions_user(user_id)`。其余查询靠主键。

**FOREIGN KEY 级联删除。** 7 张用户数据表的 `user_id` 都带 `ON DELETE CASCADE`，删 `users` 一行，关联数据由数据库自动清空；同时孤儿行再也插不进来（FK 直接拒绝）。

早期版本没有外键，删用户靠 `_api_admin_users` 手写 8 条 DELETE —— 结果 `user_appdata` 被漏掉过，库里真的留下了 `user_id=12` 的 23 行孤儿数据（22 条 prompts + 1 条工作区快照，含 `selectedPlatform:'instagram'` 这类海外版残留）。漏表是结构性问题：以后每加一张用户表都要记得改那段代码。所以改成数据库层约束。

`_api_admin_users` 里那 7 条手写 DELETE 保留为双保险 —— 万一 `PRAGMA foreign_keys` 没生效（老版 SQLite、或连接没走 `get_db()`），仍能兜住；重复删是无害 no-op。

**迁移** 由 `_migrate_user_fk_cascade()` 在 `init_db()` 末尾执行（必须是最后一步，它会重建表）。SQLite 不支持 `ALTER TABLE ADD CONSTRAINT`，只能「重命名 → 建新表 → 搬数据 → 删旧表」。三个已踩过的坑：

- **先清孤儿。** 否则搬数据那步撞 FK 约束，整个迁移回滚。
- **`PRAGMA foreign_keys` 必须先关。** 重建期间旧表被 DROP 的瞬间约束不成立。且该 pragma 在事务内是静默 no-op，迁移函数会临时把连接切成手动事务模式。
- **AUTOINCREMENT 高水位要手工保存回写。** 高水位存在 `sqlite_sequence`，`DROP TABLE` 会把那一行带走，新表 seq 退回「当前最大 id」（实测 `user_models` 从 194 掉到 183）—— 删行后新增会复用已发出去过的 id。另外 `sqlite_sequence` 没有唯一约束，用不了 `ON CONFLICT`，只能先 UPDATE 没命中再 INSERT。

迁移是幂等的：7 张表都已有外键就直接跳过重建（否则每次启动都要白搬一遍全库），仅兜底扫一次孤儿。迁移失败会回滚并打印告警，服务继续以旧结构运行，不影响启动。

**全局串行锁** `_db_lock = threading.Lock()` 包住几乎所有 DB 操作。多线程服务器 + SQLite 的最简正确做法，代价是 DB 操作不并行 —— 在这个量级（单机、几十用户）不是瓶颈。

**连接策略**：短连接，每次 `get_db()` 新建、用完 `close()`，`timeout=15`。

### 3.4 迁移与 seed

`init_db()` 在每次启动时跑，全部幂等：

| 函数 | 作用 |
|---|---|
| `_migrate_stale_model_configs` | 修已知错的 base_url / 失效 key；把 `_DISABLE_MODEL_IDS`（6 个）批量置 disabled 并改名；清掉指向禁用模型的 `user_module_defaults` |
| `_seed_ark_image` | 给已有 image 模型的老用户补 Seedream 4.0 |
| `_seed_agnes_video25` | **只给 `role='admin'`** 补 Agnes Video 2.5 |
| `_scrub_builtin_model_keys` | 两轮清库里的明文厂商密钥 |

另有两个**只在注册时跑**、不属于 `init_db()` 的 seed，在 `_api_register` 的同一个事务里依次调用（播种失败连注册一起回滚，不留"有账号没配置"的半成品）：

| 函数 | 作用 |
|---|---|
| `_seed_new_user_models` | 给新用户播种服务端托管密钥的内置模型（`api_key` 落库为空串） |
| `_seed_new_user_prompts` | **新用户复用管理员当前的提示词配置** |

`_seed_new_user_prompts` 的种子取的是 `user_prompts` 表里 `role='admin'`（`ORDER BY id LIMIT 1`，站点实际只有一个管理员，但该列无唯一约束，不加 LIMIT 会把多个 admin 的提示词混插）的**实时行**，而不是 `index.html` 里的 `defaultPrompts` 常量 —— 管理员在「提示词配置」页改过的内容才是"管理员的配置"。

幂等三保险：只在注册路径调用（老用户走 `_api_login`，不经过）+ `INSERT OR IGNORE` 撞 `UNIQUE(user_id, prompt_id)` 就跳过 + `users.prompts_seeded` 置 1（该列从建库起就在 schema 里但一直没人读，正好拿来当闸）。

全新库里 admin 还没登录过时管理员表是空的，此时拷 0 条，前端 `bootAppData()` 里"拉到空就用 `defaultPrompts` 铺一份"的兜底照旧生效 —— **那段前端代码不是多余的重复，是兜底，别顺手删。**

**"禁用而非删除"的约定**：厂商侧不可用的模型（欠费/额度/端点失效/未上线）统一 `status='disabled'` + 名字里写明原因，不从代码里删。恢复后在 UI 里改成 active 即可，零代码改动。`agnes-video-25` 就是这样交付的 —— 代码按正式文档接全，但厂商返回 503 `model_not_found`。

**幂等实现模式**：`INSERT OR IGNORE` + `NOT IN (SELECT ...)` 双保险，配合 `UNIQUE(user_id, model_id)` 约束。

### 3.5 内置模型密钥的三道闸

这是整个后端最关键的安全设计。`BUILTIN_MODEL_KEY_VARS` 是 `model_id → 环境变量名` 的唯一映射表（12 条），三处引用它：

```
① GET /api/data/models
     'apiKey': '' if model_id in BUILTIN_MODEL_KEY_VARS else r['api_key']
     └─ 读时强制脱敏，不依赖数据是否迁移过

② POST /api/data/models
     内置 model_id → 强制 api_key=''
     自定义模型若 api_key 恰为平台密钥 → 也置空
     └─ 写时拒绝落库

③ _scrub_builtin_model_keys（启动时）
     第 1 轮：清所有内置 model_id 的行
     第 2 轮：清任意 model_id 但 api_key 恰为平台密钥的行
     └─ 应对"把内置端点手动加成自定义模型"的绕过写法
```

不做这个的后果，代码注释里写得很直白：任何注册用户 F12 打一次 `/api/data/models` 就能抄走全部厂商密钥。

兜底还有 `_server_key_for_url(url)` —— `handle_custom_model` 用**完整 URL 精确相等**匹配 `API_ROUTES` 取服务端密钥。**刻意不做前缀匹配**，否则 `https://apihub.agnes-ai.com/v1/videos/../api/evil` 能骗出密钥。

### 3.6 SSRF 防护

`_assert_public_url(url)` 五步：

1. scheme 必须 http/https（挡 `file://` `gopher://`）
2. 必须有 hostname
3. 挡 `localhost` / `localhost.localdomain`
4. `getaddrinfo()` 解析，失败即拒
5. **遍历所有解析结果**，任一命中 `_is_blocked_ip` 即拒（防 DNS 轮询里藏一条内网地址）

`_is_blocked_ip` 用 `ipaddress` 判定，挡：private / loopback / **link_local（含 169.254 云元数据端点）** / multicast / reserved / unspecified。解析不出来的一律当危险。

**重定向**：`_NoRedirect` 把 3xx 抛成 `HTTPError`；`fetch_remote_media` 手动逐跳 `urljoin` 并**重新校验**，最多 3 跳。

**一个已知不对称**：`handle_product_scrape` 调用前做了 `_assert_public_url`，但 `_fetch_url` 内部用默认 opener（**自动跟随重定向**），所以商品抓取存在"公网 URL → 302 → 内网"的绕过窗口。`fetch_remote_media` 的逐跳校验才是完整版本。

### 3.7 抓取子系统

`server.py` 里近三分之一的函数是抓取解析（49 个"其他"方法中约 25 个），分四层：

```
_fetch_url()        伪装 Chrome 131 完整客户端提示头（sec-ch-ua* / Sec-Fetch-*）
                    Accept-Language: zh-CN（抓取目标全是国内站）
                    手动 gzip/deflate 解压 + charset 猜测
  ↓
_looks_like_antibot()   12 条拦截页特征 + 启发式（<20KB 且无商品结构信号）
  ↓
解析器链（按**页面结构**降级，不按站点名）：
  _parse_amazon（ld+json 商品结构）→ _parse_shopify（Shopify 形状 DOM）
  → _parse_shopify_json → _parse_shop_api_json
  → _parse_ldjson_product → _parse_microdata_product → _parse_generic
  ↓
_collect_page_images / _extract_bullets_from_html / _pick_meta
```

**`_parse_amazon` / `_parse_shopify*` 的名字是历史遗留，不代表站点绑定。** 它们实际认的是"标准 ld+json 商品结构"和"Shopify 形状的 DOM"，而国内不少独立站（有赞 / 微盟建的商城）正是这两套结构之一，所以链条一条都没删 —— 删了是净损失抓取覆盖面。函数名保留原样是为了按名搜索还能对上代码。

浏览器指纹头不是装饰 —— 代码注释记录了实测差异：**不带这些头拿到 3.7KB 验证码页，带上拿到 2.4MB 真实页面**。`Accept-Language` 从 `en-US` 换成 `zh-CN` 是国内化时改的（发 en-US 会让一部分国内站吐英文版或跳国际站），其余指纹头一个没动 —— 缺了会被判机器人。改完对内置的 8 个当当样例 URL 实抓验证过，8/8 通过。

**反爬命中时返回 HTTP 200 + `success:false` + `antibot:true`**，而不是 5xx。理由：这不是服务端错误，前端需要正常渲染三条可操作建议（重试 / 换规范详情页链接 / 手工粘副文本）。

另有"站名冒充商品名"拦截：仅在无 price 且无 sku 时，判 `og:title == og:site_name`，防把站点首页标题（如 "当当网"）当成商品名。

### 3.8 媒体落盘

图片和视频**落到服务器磁盘**，不只存厂商 URL —— 厂商链接会过期。

| | `/api/data/image` | `/api/data/media` |
|---|---|---|
| 入参 | base64 data-URI | 远端 URL（服务器去抓） |
| 上限 | 32MB（`MAX_BODY_BYTES`） | 80MB，**边读边计数**（256KB/块） |
| 类型 | png/jpg/jpeg/webp/gif，非白名单强制降级 png | 按 Content-Type 映射，映射不到才看 URL 后缀，仍只认白名单 |
| 路径 | `data/users/<uid>/images/<24hex>.<ext>` | `data/users/<uid>/{videos,images}/<24hex>.<ext>` |

**文件名由服务端 `secrets.token_hex(12)` 生成，从不接受客户端传路径。** 代码注释记录这曾是漏洞：早期 `_api_assets` POST 用 `data.get('file_path','')`，任何登录用户 POST 一个 `file_path` 再 DELETE 就能删服务器任意文件。现在该字段**写死空串**，删除前还有 `_safe_unlink_user_file()` 用 `realpath` 前缀比对兜底。

**80MB 上限边读边计数而不是信 `Content-Length`** —— 注释原话："Content-Length 可以撒谎"。

### 3.9 demo.mp4 的分片逻辑

53MB 视频（实测 55,367,779 字节），`_DEMO_CHUNK = 2MB` 分片，64KB 一块流式 write（`read(min(65536, remaining))`）。关键取舍：

```python
# 截断只在客户端确实发了 Range 时做
if partial and end - start + 1 > _DEMO_CHUNK:
    end = start + _DEMO_CHUNK - 1
```

**没带 Range 的请求返回 200 + 完整 Content-Length** —— 播放器靠这个数字算总时长，回 206 会让它以为文件只有 2MB。这是唯一允许缓存的响应（`_allow_cache = True` 跳过全局 no-store），否则每次刷新重下 53MB。

对比：`/api/data/media/<id>` 的 Range **无分片上限**且一次性 `read()` 进内存 —— `bytes=0-` 会把整个视频（≤80MB）读进内存。已知不一致，并发观看多时留意。

## 四、安全架构

### 4.1 认证链

```
POST /api/auth/login
  ↓ username 用 COLLATE NOCASE 匹配（不区分大小写）
  ↓ verify_password(): PBKDF2-HMAC-SHA256, 200,000 轮, 每用户独立 16 字节 salt
  ↓ hmac.compare_digest() 恒定时间比较
  ↓ _create_session(): secrets.token_urlsafe(32) → 256bit CSPRNG
  ↓ 写 sessions 表（token 作 PK，expires_at = now + 7d）
  ↓ Set-Cookie: gs_session=...; Path=/; HttpOnly; SameSite=Strict; Max-Age=604800
                 [+ Secure 当 GS_COOKIE_SECURE=1]

后续每个请求
  ↓ _current_user(): 读 cookie → 单条 JOIN sessions×users → 比 expires_at
  ↓ 过期即 DELETE 该行并返回 None（懒清理）
  ↓ _require_auth() → 无则 401；_require_admin() → 非 admin 则 403
```

**无滑动续期**：7 天后必须重登。**主动失效**：logout / 改密码（删本人全部 session）/ admin 重置密码或删用户（删目标全部 session）。

### 4.2 已有机制

| 面 | 实现 | 状态 |
|---|---|---|
| 密码 | PBKDF2-SHA256 20 万轮 + 每用户 salt + 恒定时间比较 | ✅ |
| 会话 | 256bit CSPRNG + HttpOnly + SameSite=Strict + 服务端表 | ✅ |
| SQL 注入 | 全部参数化。三处 `%` 拼接只拼占位符个数（`','.join('?')`），值走元组绑定 | ✅ 无注入面 |
| 数据隔离 | 一律 `WHERE user_id = ?` 写进 SQL，无"先查到再判属主"的时间窗 | ✅ |
| 厂商密钥 | 三道闸（见 3.5） | ✅ |
| SSRF | `_assert_public_url` + 逐跳重校验 | ✅（商品抓取有重定向窗口） |
| 静态文件 | 白名单 8 个文件；**黑名单优先于白名单**；反斜杠归一化防 Windows 绕过 | ✅ 实测 `/server.py` `/.env` `/data/app.db` 全 404 |
| 路径穿越 | 文件名服务端生成 + `realpath` 前缀校验 | ✅ |
| 请求体 | 用户 API 32MB，超限**不读那些字节**直接拒绝 + `close_connection` | ✅ |

| 源码凭据 | 6 个密钥常量都是 `os.environ.get(VAR, '')`，无回落字面量 | ⚠️ 见 4.4 |

### 4.3 必须在部署层补的三件事

代码里没有，也不打算在代码里做（反向代理是更合适的位置）：

| 缺口 | 实测证据 | 部署层补法 |
|---|---|---|
| **17 条厂商代理无鉴权** | 无 cookie `POST /api/ark_text` → **HTTP 200**，返回真实生成结果 `usage:{total_tokens:48}`，烧服务端 `ARK_API_KEY` | Nginx location 正则 + IP 白名单或 Basic Auth |
| **登录无限流、无锁定** | `_api_login` 无失败计数、无验证码、无延迟 | `limit_req_zone` + fail2ban |
| **注册完全开放** | 无邀请码、无验证码，任何人可自助注册 | Nginx `deny all` on `/api/auth/register` |

放大第一条的是 `send_cors()` 对每个响应发 `Access-Control-Allow-Origin: *` —— **任何第三方网站的 JS 都能匿名调这些路由**。因为没有 `Allow-Credentials: true`，`*` 本身不泄露凭据（浏览器不会带 cookie），但它让烧额度变成任何人都能做的事。

`/api/web_search`、`/api/product_scrape` 两个 GET 端点同样无鉴权，可被当免费抓取代理。（原先还有第三个 `/api/overseas_search`，国内化时整条腿已删除，现在实测返回 404。）

配置和验证命令见 [Ubuntu 部署指南](../deploy/Ubuntu部署指南.md) 第四节 —— 那段 location 正则做过双向验证：17/17 代理路由 + 2 个裸 GET 端点全覆盖，11 个已鉴权接口零误伤。

### 4.4 已知源码级问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 残留失效 key 明文 | `server.py:339` `_STALE_MODEL_FIXES` | 一个已失效的 Seedance 旧 key 作为"要被替换掉的错值"存在。功能上必要，但违反"源码不含凭据"原则 |
| `GS_ADMIN_PASS` 默认值明文 | `server.py:180` | 默认 `sunny520` 公开可见。`deploy.sh` 会换成随机值，手动部署会踩 |
| 管理员之间无隔离 | `_api_admin_users` POST | 管理员可重置其他管理员的密码（DELETE 分支明确禁止删管理员，两个分支权限模型不一致） |
| 代理分支请求体无上限 | `do_POST` 代理分支 | 绕过 `_read_json_body`，直接 `rfile.read(content_length)` 无限制。靠 Nginx `client_max_body_size` 兜 |
| 无 SIGTERM handler | `main()` | 只有 SIGINT 走优雅关闭。systemd 默认 SIGTERM 会硬掐。不丢数据（WAL + 逐操作 commit），但飞行请求被断 |

## 五、配置与运行

### 5.1 配置优先级

```
真实环境变量（systemd EnvironmentFile）
  ↓ 覆盖不了 —— _load_dotenv 只填空缺
项目根 .env
  ↓ 都没有
os.environ.get(VAR, '') 的默认值
```

`_load_dotenv()` 是自己实现的（43 行）：`utf-8-sig` 编码、`#` 注释、成对引号剥离、**已存在且非空的环境变量不覆盖**。这条规则让 systemd 的 `/etc/globalsales.env` 稳定压过项目里的 `.env`。

**反向写入**：管理员在「大模型配置」保存内置模型密钥时，`_persist_env_keys()` 同名行原地替换、值含换行直接拒绝、新建文件尝试 `chmod 600`，并同步更新 `os.environ` + 模块常量 + `API_ROUTES` 的 `auth_key` —— **无需重启即时生效**。只由 admin-only 的 `/api/sync_config` 调用。

| 变量 | 默认 | 说明 |
|---|---|---|
| `GS_PORT` | `8766` | 监听端口 |
| `GS_COOKIE_SECURE` | `0` | `1` 时 cookie 加 `Secure`。**http 下设 1 会导致永远登不上** |
| `GS_ADMIN_USER` / `GS_ADMIN_PASS` | `martinxie` / `sunny520` | **仅首次建库生效** |
| `ARK_PLAN_API_KEY` | 空 | 火山方舟 Agent Plan —— **文案主力**（7 个文本模块的默认模型 `ark-plan-text` 用它） |
| `ARK_API_KEY` | 空 | 火山方舟 Seedream —— **出图主力**（图片类唯一可用模型） |
| `SEEDANCE_MINI_API_KEY` | 空 | 视频默认引擎 |
| `AGNES_API_KEY` / `MM_API_KEY` / `HY_API_KEY` | 空 | 备选厂商 |

**`ARK_PLAN_API_KEY` 和 `ARK_API_KEY` 是两把不同的 key，不可互换**（`.env.example` 里也写了这点）：

```
ARK_API_KEY      → api/v3/images/generations        （Seedream 出图）
ARK_PLAN_API_KEY → api/plan/v3/chat/completions     （文本 + 图片理解）
```

互换会分别拿到 404 `UnsupportedModel` / 401 `AuthenticationError`。这是部署时最容易踩的一格 —— 只配 `ARK_API_KEY` 的话站点能登录、能出图，但所有文案功能报鉴权错。

6 个密钥默认空串、源码无字面量。没配就明确报鉴权错误 —— 宁可报错也不为"开箱能跑"把密钥焊回源码，因为源码会被拷贝、打包、上传。

### 5.2 进程模型

```python
ThreadingHTTPServer(('0.0.0.0', PORT), ProxyHandler)   # 注意：绑所有网卡
  daemon_threads = True
  allow_reuse_address = True
```

自定义的 `ThreadingHTTPServer` **同名 shadow 掉标准库的**。多线程是必需的 —— 视频生成要轮询几分钟，单线程会阻塞整个服务。

`handle_error` 被 override：`ConnectionReset/Aborted/BrokenPipe` 只打一行摘要不打 traceback（浏览器刷新会掐掉飞行中的请求，尤其 `beforeunload` 那次 `saveAppData`），其余异常仍走完整打印。

**HTTP 版本**：未设 `protocol_version`，沿用默认 `HTTP/1.0`（无 keep-alive）。`_read_json_body` 里有 keep-alive 相关的 `close_connection` 防御，在默认协议下不生效 —— 无害的多余防护。

**绑 `0.0.0.0` 是部署时要处理的**：配 Nginx 后应用防火墙关掉 8766 的外部访问。

### 5.3 Python 版本下限：3.7

判据（逐条核实）：

| 特性 | 用了吗 | 要求 |
|---|---|---|
| `datetime.fromisoformat()` | ✅ 用了 | **3.7+ ← 硬下限** |
| `sys.stdout.reconfigure()` | ✅（有 `hasattr` 保护） | 3.7+ |
| f-string | ✅ 73 处（`ast.JoinedStr` 计数） | 3.6+ |
| 海象 `:=` | ❌ 零命中 | — |
| `match` 语句 | ❌ 零命中 | — |
| 新式类型注解 | ❌ 全文无类型注解 | — |

Ubuntu 20.04 自带 3.8、22.04 自带 3.10、24.04 自带 3.12，全部满足。**零 pip 依赖**，无需 venv。

## 六、扩展指南

### 加一个文本/图片模型

1. `server.py`：`API_ROUTES` 加路由 → `BUILTIN_MODEL_KEY_VARS` 加映射 → `sync_models_to_files` 的 `route_by_id` 加条目
2. `index.html`：`defaultModels` 加条目
3. `.env` / `.env.example`：加 key 变量

### 加一个视频模型（比上面麻烦，容易漏）

除上述外还要改 5 处：

1. `VIDEO_MODEL_BUILTIN` 注册调用函数
2. `_videoShortKey` 加 `model_id → 短键` 映射
3. **4 个 dispatch 点**各加一个 `else if` 分支：`generateVideo` 单段、`generateVideo` 分镜、`vcGenerate`、`vcGenSegments`
4. **5 处显示名映射**：2 个 `genVideoModelNames`、1 个 `modelLabels`、2 个 `vcModelNames`、2 个 `vcPlatformNames`
5. 分辨率徽标（若档位不同）

厂商未放量时按 `agnes-video-25` 的模式交付：`_DISABLE_MODEL_IDS` + `_DISABLE_MODEL_NAMES` 里写明原因 + 一条 `_seed_*` 函数，代码按正式文档接全但状态 disabled。

### 加一个功能页

1. nav 按钮插进对应分组（注意 `nav-divider` 位置）
2. `<section id="section-xxx">` 插进 `<main>` 对应位置。**不要给它加 `.active`** —— 首页由 `init()` 里的 `scrollToSection(currentSection)` 点亮，多一个 `.active` 会同时显示两页
3. 不需要再登记 section 顺序 —— 单页导航下当前页由 `scrollToSection` 直接决定，历史上那份手写的 sections 数组（曾漏 5 项导致高亮错位）已删除
4. `DEFAULT_MODULE_MODELS` + `MODULE_MODEL_TYPE` 加条目（若需要模型选择器）
5. `<div data-model-picker="xxx">` 由 `initModelPickers` 自动装配
6. `window.I18N.zh` 加键（**只有 zh 一个字典**，国内化后英文词典已删除）。注意 `applyI18n` 用的是 `el.textContent = t(key, el.textContent)` —— **HTML 里的中文 fallback 是 applyI18n 跑之前显示的内容**，改了字典没改 HTML（或反之）就会两边不一致，这是本项目最反复踩的坑。带 `<strong>` 的句子不能挂 `data-i18n`，会被扁平化
7. 需要持久化的输入框加进 `WORKSPACE_INPUT_IDS`
8. 加一条 `#nav-xxx .nav-icon { color: ... }`（不加就是继承的灰色，在一排彩色图标里很突兀）。选色守两条：tailwind 400/500 档、与**同组相邻项**色相隔开 30° 以上

### 加一个弹窗

1. 静态弹窗（写在 HTML 里）：往 `ESC_MODALS` 末尾加 `{ id, close }`。**顺序即优先级，靠后的先关**，所以叠在最上面的放最后
2. 动态弹窗（JS 建的）：创建时 `pushEscLayer(el, closeFn)`，关闭后 `popEscLayer(el)`
3. `close` 走**已有的 `close*()` 函数**，别直接 `display:none` —— 定时器、编辑态、`body.overflow` 都在那些函数里清
4. close 函数必须**可重复调用**（点遮罩关完再按 ESC 是常见操作），先判 `parentNode` 再 `removeChild`
5. 别用 `offsetParent` 或裸 computed display 判可见，用 `isModalVisible()`，理由见 2.6

### 加一个后端端点

1. `handle_user_api` 里加分支，**第一行就是** `u = self._require_auth(); if not u: return`
2. 所有 SQL 带 `WHERE user_id = ?`
3. 需要抓外部 URL 就先 `_assert_public_url()`
4. 抓回的 HTML 过 `_looks_like_antibot()`
5. `_read_json_body()` 读 body（自带 32MB 上限）
